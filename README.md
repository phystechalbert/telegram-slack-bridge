# Telegram ↔ Slack

Мост собирает переписку из Telegram в одном закрытом канале Slack. У каждого личного чата, группы или темы форума свой тред. В треде можно обсуждать сообщение с коллегами. Чтобы отправить текст собеседнику, начните ответ с `!tg-send`. Мост вернёт в тред номер сообщения в Telegram.

Работает на Cloudflare Workers. Привязки чатов к тредам, очередь и квитанции хранятся в SQLite внутри Durable Object. Для установки нужны собственные приложения Telegram и Slack.

## Что можно пересылать

| Из Telegram в Slack | Из Slack в Telegram |
| --- | --- |
| Сообщения личных чатов подключённого Telegram Business, выбранных групп, тем и каналов | Текст, ссылки и один прикреплённый PDF до 5 МиБ |
| Фото, документы, голосовые, видео, видеосообщения, анимации, аудио и стикеры до 20 МиБ | Подпись к PDF до 1024 символов, текст без файла до 4096 |
| Контакты, геопозиции и опросы в текстовом виде. Каждый элемент альбома приходит отдельно | Отправка сразу или в назначенное время. Публиковать в Telegram-канал может владелец, заданный в настройках |

Для личных чатов бот принимает обновления Telegram Business. По умолчанию он отвечает по Bot API в пределах 24 часов после последнего входящего сообщения. Можно дополнительно подключить пользовательский аккаунт через MTProto. Тогда ответы в личных чатах идут от него, доступны адресная книга, открытие чата, правки и статус прочтения. [Telegram Business Bot API](https://core.telegram.org/bots/api#businessbotrights)

## Команды в Slack

| Команда | Результат |
| --- | --- |
| `!tg-send Текст` или `!tg-send-now Текст` | Отправить в чат текущего треда. Для документа прикрепите PDF к тому же сообщению. Можно написать только `!tg-send` и приложить файл |
| `!tg-send-at <дата-и-время> Текст` | Запланировать текст за 1 минуту – 72 часа. Время в ISO 8601 с часовым поясом, например `2030-04-05T14:30+03:00`. Введите свою дату |
| `!tg-send-list`, `!tg-send-cancel <S-id>`, `!tg-send-cancel all` | Посмотреть или отменить ожидающие отправки этого треда |
| `!tg-edit <message_id> Новый текст` | Исправить своё исходящее сообщение или подпись к фото/файлу в личном чате. ID виден в квитанции об отправке. После правки мост перечитывает сообщение и показывает подтверждённый текст |
| `!tg-read-status` | Показать, прочитано ли последнее исходящее сообщение в личном чате. Точное время зависит от того, отдаёт ли его Telegram |
| `!tg-chat-open @username` | Открыть или найти тред для человека, в том числе до его первого сообщения. Поддерживаются ссылка t.me, международный номер и числовой Telegram ID. Команда доступна владельцу Slack. Первое сообщение отправляется отдельным `!tg-send` |
| `!tg-contact-read <chat_id>` | Показать текущее сохранённое имя и username. Chat ID указан в заголовке треда |
| `!tg-contact-add <JSON>`, `!tg-contact-rename <JSON>` | Подписать или переименовать контакт из его треда. Мост проверяет исходные данные и перечитывает контакт после записи |
| `!tg-contact-add-phone <+номер> <имя>` | Сохранить контакт по телефону, который Telegram позволяет сопоставить с аккаунтом. Можно вызвать в корне закрытого канала. Уже существующий контакт сохраняет своё имя |

Пример работы с адресной книгой. Сначала выполните `!tg-contact-read` с ID из заголовка. При добавлении подставьте увиденный username. Пустая строка означает, что у человека нет username.

```text
!tg-contact-add {"chat_id":"<ID из треда>","first_name":"Алекс","last_name":"","expected_username":"<текущий username>"}
!tg-contact-rename {"chat_id":"<ID из треда>","first_name":"Алекс","last_name":"Дизайн","expected_first_name":"Алекс","expected_last_name":""}
```

Сохранённое имя появится у следующих входящих сообщений. Переименование в Telegram сохраняет историю уже опубликованных сообщений в Slack.

## Установка

1. Установите Node.js 22.13+ и выполните `npm ci`. Проверьте сборку командой `npm run test:worker`.
2. Создайте приложение Slack в своём workspace. Шаблон прав лежит в [slack-manifest.json](slack-manifest.json). Для первого импорта удалите из копии шаблона блок `event_subscriptions`: адрес обработчика появится после публикации Worker. Установите приложение, создайте закрытый канал и пригласите в него бота. App ID и Signing Secret находятся в **Basic Information**, Bot User OAuth Token — в **OAuth & Permissions**. [Создание Slack-приложения](https://api.slack.com/apps)
3. Создайте бота в BotFather. Для личных переписок включите Business Mode и подключите бота в настройках Telegram Business нужного аккаунта. Выберите доступные боту чаты и разрешите отвечать. Для групп добавьте бота и настройте получение сообщений с учётом Privacy Mode. Для канала дайте ему соответствующие права. [Telegram Bot FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get)
4. Войдите в **свой** аккаунт Cloudflare через `npx wrangler login`. Выберите свободное имя Worker в `wrangler.toml`, выполните `npm run deploy` и запомните его HTTPS-адрес. Затем добавьте значения из таблицы ниже в **Worker → Settings → Variables and Secrets** и примените конфигурацию. Токены, signing secret, webhook secret и учётные данные MTProto задавайте как **Secret**. [Настройки секретов Workers](https://developers.cloudflare.com/workers/configuration/secrets/)
5. В Slack включите **Event Subscriptions**, укажите `https://<ваш-worker>/slack` и добавьте событие бота `message.groups`. Дождитесь статуса **Verified**. Если Slack попросит, переустановите приложение. [События закрытого канала](https://docs.slack.dev/reference/events/message.groups/)
6. На локальной машине задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` в окружении, затем выполните `npm run webhook -- https://<ваш-worker>/telegram`. Команда назначает webhook выбранному боту и проверяет адрес через `getWebhookInfo`. У одного бота может быть только один webhook.
7. Напишите из разрешённого Telegram-чата. В Slack появятся корневое сообщение и ответ в его треде. Напишите в этом треде `!tg-send Проверка связи` и сверьте текст в Telegram и номер сообщения в квитанции Slack.

### Настройки

| Переменная | Значение |
| --- | --- |
| `SLACK_TEAM_ID`, `SLACK_APP_ID`, `SLACK_CHANNEL_ID` | ID workspace, приложения и закрытого канала. Нужен локальный канал без Slack Connect |
| `SLACK_SIGNING_SECRET`, `SLACK_BOT_TOKEN` | Signing Secret и токен бота приложения |
| `SLACK_ALLOWED_USERS` | ID людей, которым разрешено отправлять команды, через запятую |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` | Токен BotFather и сгенерированная вами случайная строка для webhook. Например, `node -p "require('node:crypto').randomBytes(32).toString('hex')"` |
| `TELEGRAM_OWNER_ID` | Числовой ID владельца Telegram Business. Обязателен для личных чатов |
| `TELEGRAM_PRIVATE_CHATS` | Числовые ID личных чатов через запятую. Значение `*` включает все чаты, доступные боту через Business-подключение владельца |
| `TELEGRAM_GROUP_IDS`, `TELEGRAM_CHANNEL_IDS` | Разрешённые ID групп/супергрупп и каналов соответственно, со знаком минус, через запятую. Задайте хотя бы один маршрут: личные чаты, группы или каналы |
| `TELEGRAM_OWNER_CONTEXT` | По желанию `true`, чтобы в существующих тредах видеть также сообщения, отправленные вручную из Telegram |
| `SLACK_OWNER_USER_ID` | Для открытия новых чатов и публикации в Telegram-каналы. ID должен входить в `SLACK_ALLOWED_USERS` |
| `TELEGRAM_BUSINESS_CONNECTION_ID` | Необязательная привязка к конкретному соединению. Для `!tg-chat-open` обязательна. ID приходит в поле `business_connection_id` обновления Telegram. После первого сообщения его также можно найти в таблице `conversations` своего Durable Object, в JSON-поле `route.connectionId` |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_USER_SESSION` | Для пользовательского аккаунта. Получите собственные API ID и hash в [Telegram API Development Tools](https://my.telegram.org) |

### Подключение пользовательского аккаунта

В локальном интерактивном терминале задайте `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и `TELEGRAM_OWNER_ID`. Запустите `npm run login -- <путь-к-новому-файлу.session>`. Введите телефон, код Telegram и пароль двухэтапной аутентификации, если он включён. Скрипт проверит ID вошедшего пользователя и запишет сессию в указанный файл. Храните файл как пароль от аккаунта.

Перенесите содержимое файла в secret `TELEGRAM_USER_SESSION` и задайте в Worker те же API ID и hash. На Windows можно передать сессию прямо из файла:

```powershell
Get-Content -Raw -LiteralPath .\bridge.session | npx wrangler secret put TELEGRAM_USER_SESSION
```

## Проверка и повторные доставки

`npm test` запускает тесты маршрутизации, работы с файлами и командами аккаунта. `npm run test:worker` собирает Worker и проверяет оба направления в локальном Cloudflare runtime с подменой Telegram и Slack. Для этих проверок токены не нужны.

Повтор одного webhook использует ту же запись в очереди. Если внешний сервис мог принять запись, но не вернул проверяемую квитанцию, мост останавливает повтор этой операции. Перед повторной ручной командой проверьте исходный чат. Cloudflare хранит привязки тредов и очереди в аккаунте установки. События правки входящих сообщений в самом Telegram и изменения текста команды через интерфейс Slack не запускают пересылку повторно.
